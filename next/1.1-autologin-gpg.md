# Greetd Pico OpenPGP challenge login (PIN + card signature)

## Goal

- Keep `pico-openpgp` firmware
  (https://github.com/polhenarejos/pico-openpgp, OpenPGP 3.4.1 over
  USB/CCID) as-is — no reflash to FIDO.
- Require a real cryptographic challenge at the greeter: user types
  username, enters the Pico user PIN, PAM asks the card to sign a
  nonce with its authentication subkey and verifies it against an
  enrolled public key. No Pico (or wrong Pico) → no login via this
  method.
- Supersedes the earlier presence-only autologin draft: USB
  VID/PID/serial/product are firmware strings (open-source firmware,
  `patch_vidpid.sh` exists), so a serial allowlist is forgeable with a
  $4 Pico. This design removes the serial allowlist and the
  `initial_session` autologin wrapper entirely.

## Current state (repo)

- Login: `greetd` + `noctalia-greeter-session -- --session hyprland-uwsm`
  (`files/wm/common/greetd/etc/greetd/config.toml`, user `greetd`).
- `recipes/base/systemd-homed.yml` installs `gnupg2-scdaemon` /

  runs `authselect select sssd ... with-pam-u2f` (regenerates
  `system-auth`; do NOT hand-edit `system-auth`).
- CCID `Info.plist` overlay already shipped:
  `files/wm/common/greetd/usr/lib64/pcsc/drivers/ifd-ccid.bundle/Contents/Info.plist`.
- `opensc` is NOT yet installed (in Fedora repos — provides
  `opensc-pkcs11.so`, `openpgp-tool`, `pkcs15-tool`, `pkcs11-tool`).
- `pam_p11` (OpenSC's lightweight PKCS#11 PAM module, auth against

  (`zemmert/pam_pkcs11`) and heavier — not chosen.
- Companion plan: `next/1.0-greetd-fido-autologin.md` (FIDO presence).
  Unrelated; untouched.

## Design

### 1. Make the Pico visible to `pcscd`

- `pico-openpgp` presents as a USB CCID reader with embedded OpenPGP
  card. `pcscd` only claims VID/PIDs listed in the CCID `Info.plist`.
- Default UF2 VID/PID is `2E8A:10FF` (or `FEFF:FCFD`); custom
  `USB_VID`/`USB_PID` at build time (incl. `GnuPG` preset).
- Change: append the Pico's actual VID/PID to the `Info.plist`
  overlay (read IDs via sysfs after flashing).
- Alternative (no rebuild): commission via PicoKey App.

### 2. PAM: `pam_p11` scoped to the greeter

- New recipe module (e.g. `recipes/base/openpgp-login.yml`):
  - `dnf`: add `opensc`, `pcsc-lite` (already), plus build deps for
    the build step (`gcc`, `make`, `pam-devel`, `openssl-devel`,
    `libp11-devel` / `opensc-devel` as available).
  - `script`: fetch `pam_p11-0.6.1.tar.gz` from
    `https://github.com/OpenSC/pam_p11/releases`, verify checksum,
    `./configure --prefix=/usr --libdir=/lib64 && make && make install`
    (single fixed version pinned; checksum recorded in-repo).
- PAM wiring scoped to `/etc/pam.d/greetd` (static file owned by the
  greetd package, NOT authselect-generated), so `authselect
  apply-changes` can't clobber it:
  ```
  auth sufficient pam_p11.so /usr/lib64/opensc-pkcs11.so
  ```
  placed before the `system-auth` include. Semantics: Pico present +
  PIN correct + signature verifies → login; otherwise fall through to
  existing password / `pam-u2f` stack. Key absent → module fails fast
  without prompting (password UX unchanged).
- Explicitly out of scope in v1: `login`, `sudo`, `system-auth`
  wiring (would need an authselect custom profile to survive
  regeneration — follow-up).
- PIN UX: the greeter password field carries the Pico user PIN (PW1);
  Pico press-to-confirm button acts as presence/touch factor alongside
  the PIN. Verify `noctalia-greeter` forwards PAM text prompts (it
  already handles password + `pam-u2f` cue prompts).

### 3. Enrollment (per user, no CA)

- Auth key: the OpenPGP authentication subkey, exposed by OpenSC as
  the `Authentication key` object (ID 03).
- Enroll task (`register-openpgp-key`, fish + `gum`):
  ```
  mkdir -p ~/.ssh && chmod 700 ~/.ssh
  ssh-keygen -D /usr/lib64/opensc-pkcs11.so -e >> ~/.ssh/authorized_keys
  ```
  then prune to the single Pico line; `chmod 600 authorized_keys`.
- Alternative (cert-based): `pkcs11-tool --read-object --type cert`
  → `~/.eid/authorized_certificates` (only if a cardholder
  certificate is installed on the Pico; not required in v1).
- `firstboot`: offer the same enroll step after `pamu2fcfg`; skip
  cleanly when no Pico is plugged (greeter password login unaffected).
- `unregister-openpgp-key`: remove the Pico line.

### 4. Known risks / validation points (real hardware required)

- OpenSC OpenPGP driver historically exposes signature vs auth keys
  across two PKCS#11 slots with PIN-mode quirks (PW1 modes 81/82);
  validate `pkcs11-tool -O -L` shows the auth key and a test
  `ssh-keygen -D` + `pamtester greetd $USER authenticate` round-trip
  succeeds with the Pico before wiring the greeter.
- `scdaemon` (Fedora builds use pcsc, exclusive mode) vs OpenSC
  contention: set `pcsc-shared` in `~/.gnupg/scdaemon.conf` for
  concurrent `gpg --card-status` + login use.
- If `usbguard` is ever enabled, add a CCID allow-rule.
- Lockout safety: keep `sufficient` (never `required`) in v1 so a
  broken/absent Pico never bricks password login.

# Resume sysmon session

## Goal

- `sysmon` / `sysmon toggle` restores a working layout after reboot, detach, or killed panes with no manual steps.
- Tab "monitor": btop top, nvtop bottom. Tab "services": systemd-manager-tui.
- Never start AI agents in this session (monitor-only, as built).

## Context (verified)

- `files/base/system/usr/bin/sysmon` bootstraps once: skips setup when a workspace labeled `sysmon` exists, then `exec herdr --session sysmon`.
- Herdr persists session state under `~/.config/herdr/sessions/sysmon/`; panes survive detach and server restarts restore them as shells. Only panes with a native agent session reference resume their agent (`session.resume_agents_on_restore`, herdr docs); ours hold plain commands, so after a reboot they come back as idle shells, not re-running btop/nvtop.
- No systemd unit pre-warms the herdr server; first attach/toggle starts it implicitly via the client.
- CLI surface (verified live): `herdr --session sysmon workspace list` (JSON), `pane split --direction right|down`, `pane run <id> <cmd>`, `tab create --label`, `tab rename`. No per-session agent-detection toggle exists; session stays agent-free by never calling `agent start`.

## Changes

1. `sysmon` `bootstrap()`: replace workspace-exists skip with layout verify + repair.
   - Resolve workspace `sysmon`, tabs `monitor` (expect 2 panes) and `services` (expect 1 pane) via `workspace list` / `tab list` / `pane list` JSON + `jq`.
   - Missing workspace -> current create path unchanged.
   - Existing workspace, wrong shape -> create missing tabs, split missing panes.
2. Per-pane command check before `pane run`: inspect with `pane process-info` (or `pane read --source recent`, match `btop`/`nvtop`/`systemd-manager-tui`); shell-at-prompt panes get `pane run` re-issued, running ones left alone. Idempotent re-toggle.
3. Keep lazy start (no autostart unit): first toggle after login starts the server and repairs layout in one path. Add unit only if cold-start latency proves annoying.
4. Keep `toggle()` as-is (ensure window + `togglespecialworkspace sysmon`); repair happens inside the attached `sysmon`, not in toggle.

## Verification

- `mise run check:lint`; `bash -n` + `shellcheck` on `sysmon`.
- VM 5290: reboot, `SUPER+S`, confirm btop/nvtop/tui running (no manual input); kill one pane, re-toggle, confirm repair; detach (`prefix+q`), re-toggle, confirm state kept.
- Confirm `herdr agent list` empty for session `sysmon`.

## Decisions made

- Repair-on-attach, not exact process restore (herdr only restores agents natively).
- Lazy server start; no systemd pre-warm unit for now.
- Session stays agent-free by construction (no `agent start`), no config override.

# Try Kierownik Windows Plan

## Overview

Start inside kierownik: one generic VM recipe + reuse existing tasks. No new repo yet. Goal: Fedora bootc qcow2 boots under WHPX with Hyprland + virgl/Venus, scripts-first launcher later.

## Architecture

- **Guest**: Fedora bootc qcow2, Hyprland, virtio drivers, virgl/Venus, virtio-9p share, optional SSH/port-forward.
- **Hypervisor**: Windows Hypervisor Platform (WHPX), same stack WSL2 uses. No Hyper-V role required.
- **Graphics**: virgl + Venus Vulkan (WINQ-EMU), llvmpipe fallback.
- **Launcher (phase 1)**: PowerShell scripts, no Go exe. `bootstrap.ps1` + `launch-kierownik.ps1` + `diagnostics.ps1`.
- **Launcher (phase 2)**: Full Go `TryKierownik.exe` (forked from try-omarchy-windows), tray, Settings UI, signed updates, Start-menu shortcuts.

### 4. WHPX Proving

**Current `run/vm`** (KVM):
```bash
exec qemu-system-x86_64 \
  -enable-kvm \
  -cpu host \
  -machine q35,smm=on \
  -m 8192 -smp 8 \
  -drive if=pflash,format=raw,readonly=on,file="${code}" \
  -drive if=pflash,format=raw,file="${vars}" \
  -drive file="${disk}",format=qcow2,if=none,id=disk0 \
  -device virtio-blk-pci,drive=disk0,bootindex=1 \
  -nic user,model=virtio-net-pci \
  -device virtio-vga-gl \
  -display gtk,gl=on \
  -device qemu-xhci \
  -device usb-tablet \
  -boot menu=on
```

**Windows twin** (WHPX):
```bash
exec qemu-system-x86_64 \
  -accel whpx \
  -machine q35 \
  -cpu qemu64 \
  -m 8192 -smp 4 \
  -drive if=pflash,format=raw,readonly=on,file="${code}" \
  -drive if=pflash,format=raw,file="${vars}" \
  -drive file="${disk}",format=qcow2,if=none,id=disk0 \
  -device virtio-blk-pci,drive=disk0,bootindex=1 \
  -nic user,model=virtio-net-pci \
  -device virtio-gpu,virgl=on \
  -device virtio-gpu-pci,virgl=on \
  -display sdl,gl=on \
  -device qemu-xhci \
  -device usb-tablet \
  -boot menu=on
```

**Key flags**:
- `-accel whpx` (no `-enable-kvm`)
- `-machine q35` (no `smm=on`)
- `-cpu qemu64` (no `host`)
- `-device virtio-gpu,virgl=on` (no `virtio-vga-gl`)
- `-display sdl,gl=on` (no `gtk,gl=on`)
- `qemu-guest-agent` + `spice-vdagent` enabled in guest for host integration

**Logging**:
- Log QEMU args to `logs/whpx-boot.log`
- Capture guest console to `logs/whpx-console.txt`
- Document findings in `docs/FINDINGS.md` (WHPX wedges, reboot relaunch, shutdown cleanup)

**CI**: Keep VM out of `.github/workflows/build.yml` matrix like N100/WSL.

### 5. Launcher (Phase 1) - Scripts Only

**Repo**: `try-kierownik-windows` (new repo, MIT fork from try-omarchy-windows).

**Structure**:
```
app/ (phase 2 only)
runtime-build/ (WINQ-EMU pin + verify)
guest-build/ (only patches/docs, no full builder)
scripts/bootstrap.ps1
scripts/launch-kierownik.ps1
scripts/diagnostics.ps1
docs/FINDINGS.md
docs/COMPATIBILITY.md
docs/TESTING.md
```

**`scripts/bootstrap.ps1`**:
- Enable WHPX feature via `dism.exe /online /enable-feature /featurename:Microsoft-Hyper-V-All /all /norestart`
- Prompt restart
- Download WINQ-EMU portable tree (~84MB) + `krw-VM.qcow2` + `SHA256SUMS` from GH releases
- SHA256 verify `.part` files, resume on byte-range support
- Create `%LOCALAPPDATA%\TryKierownik` layout:
  - `disk.raw` (sparse NTFS/ReFS)
  - `runtime/` (WINQ-EMU)
  - `payload/` (release manifest + checksums)
  - `state/` (settings, manifests, install receipts)
- No `gum` here, PowerShell only.

**`scripts/launch-kierownik.ps1`**:
- GPU/CPU auto-detect (probe virgl, fallback llvmpipe)
- QMP control plane for VM lifecycle
- Win-key scoped to window only (PowerShell `Add-WinEventLog` + `Set-ConsoleLayout`)
- Ctrl+Alt+F fullscreen, Ctrl+Alt+G grab
- virtio-9p share mount (`Kierownik Shared` in Windows home)
- `-ssh/-forward` loopback only (127.0.0.1:2222:22, tcp:8080:80, etc.)
- `-reclaim` to write zeros, shrink disk on shutdown
- `-diagnostics` zip (logs + redacted settings, no disk images)

**`scripts/diagnostics.ps1`**:
- Collect QEMU logs, guest console, `settings.json`, `vm/shell.log`, `vm/state.json`
- Redact known account paths, SSH keys
- Zip to `diagnostics/try-kierownik-<timestamp>.zip`

**Documentation**:
- `docs/FINDINGS.md`: WHPX wedges, reboot relaunch, shutdown cleanup, GPU probing quirks.
- `docs/COMPATIBILITY.md`: Tested Windows versions, GPU support (Radeon iGPU verified), VM limits (NVIDIA CUDA/OptiX not provided, no native PCI passthrough).
- `docs/TESTING.md`: Local WHPX testing steps, expected boot time, troubleshooting.

## Build Order

1. Create `recipes/krw-VM.yml`
2. Create `recipes/vm/all.yml` + `files/vm/all/`
3. Run `mise run check:lint` (validates recipe + tasks)
4. Run `mise run build:oci VM` (builds OCI)
5. Run `mise run build:qcow2 VM` (builds qcow2)
6. Run `mise run run:vm VM` (local KVM test, verify Hyprland boots)
7. Port WHPX args to new `scripts/launch-kierownik.ps1`
8. Test on Windows with WHPX, document findings

## Known Gaps

- **Guest autologin**: `greetd` + noctalia greeter must work headless. If not, add `files/vm/all/firstboot.sh` for user creation.
- **WHPX boot**: bootc qcow2 under WHPX unproven. Omarchy uses direct kernel boot; bootc needs full qcow2 + GRUB + OSTree. Test and fix.
- **GPU rendering**: virgl + Venus via WINQ-EMU not yet tested. Start with llvmpipe fallback.
- **Launcher**: only scripts now. Go app deferred.

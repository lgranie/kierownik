### Fix worthy

1. [DONE 2026-09-17] `kernel: Malformed early option 'amd_pstate'`: root cause `amd_pstate=epp` in `recipes/cpu/amd.yml:19`. Valid values are only `disable/passive/active/guided` (kernel `amd-pstate.c` + `admin-guide/pm/amd-pstate`). Fixed to `amd_pstate=active`, preserves current `amd-pstate-epp` + `powersave` behavior observed on host (`/sys/devices/system/cpu/amd_pstate/status = active`). `mise run check:lint` passed.
2. [DONE 2026-09-17] `kvm_amd: [Firmware Bug]: Cannot enable x2AVIC, AVIC unsupported`: CPU `Ryzen 7 8745HS` reports `x2avic` flag, but IVHD `EFR2:0x0` shows BIOS disabled AVIC; `kvm_amd avic=N`. No recipe change — host-only BIOS fix (enable SVM + IOMMU + AVIC/x2AVIC, update BIOS). KVM falls back to legacy interrupt remapping (`AMD-Vi: Interrupt remapping enabled`), safe to ignore until BIOS fixed. Bonus fix in same file: dropped invalid `amd_iommu=on` from `recipes/cpu/amd.yml` (`AMD-Vi: Unknown option - 'on'`; valid values are `off/force_isolation/force_enable/...`, no `on`). IOMMU already active via BIOS (groups 0-18 listed), so drop preserves behavior and silences warning. `intel_iommu=on` left intact (valid on Intel). `mise run check:lint` passed.
3. [DONE 2026-09-17] `systemd-logind[1168]: Failed to open '/boot/loader/entries': Remote address changed`: boot-order race, benign. Timeline `10:19:44`: `logind` starts → `boot.mount` mounts `/boot` (ext4 nvme0n1p2) → `boot-efi.mount` → logind hits entries dir mid-mount, gets `EREMOTECHANGED` once. Post-boot `/boot/loader/entries` readable (`ostree-1.conf`, `ostree-2.conf`), sessions fine (`greetd c1`, `lgranie wayland`). No recipe change — upstream logind has no `After=boot.mount` by design; entries only needed for reboot-to-menu D-Bus. Adding a drop-in would delay login for one cosmetic line. Note: host `/proc/cmdline` still shows old `amd_pstate=epp amd_iommu=on` (old deployment, fixes land on next build).
4. [DONE 2026-09-17] `kernel: IPv4: martian destination (src=192.168.8.1, dst=0.0.0.0, dev=br0)`: benign DHCP race, no fix. Timeline: `br0` up `10:19:44`, ports `enp2s0`/`eno1` attached `10:19:46-47`, DHCP transaction restarts, martian at `10:19:52`, lease `192.168.8.117` at `10:19:54`. `192.168.8.1` = upstream DHCP server, `dst 0.0.0.0` = DHCPOFFER/ACK to address-less client (host itself pre-lease, or L2-forwarded client offer visible on transparent bridge `enp2s0 uplink + eno1 clients`, `recipes/wm/8745.yml`). Logged only because hardening sets `net.ipv4.conf.all/default.log_martians=1` (`files/base/system/etc/sysctl.d/60-hardening.conf:59-60`). Keep logging; silencing via `net.ipv4.conf.br0.log_martians=0` would weaken spoof detection on uplink. No recipe change.
5. [DONE 2026-09-17] `irqbalance[1150]: thermal: failed to receive messages / Failed to initialize thermal events`: benign, no repo change. Source is `irqbalance-1.9.5` (distro default, not repo-managed; repo only handles `power-profiles-daemon` in `recipes/base/power-mgmt.yml`), not ACPI — zones healthy (`TZ01 61C`, `k10temp Tctl` live, noctalia sysmon reads `36C`). Daemon continues degraded: falls back without thermal-event input, plus `Cannot change IRQ 60-67 affinity: Permission denied` (sandbox/pinned IRQs marked unmanaged). Single-node `8745HS` laptop gains little from irqbalance anyway; disabling or adding `--nothermal`-style overrides would deviate from distro default for two cosmetic lines. Revisit only with measured IRQ-latency win.

# Pico hardware key lifecycle (`key:init/create/copy/update`)

## Goal

- One `krw key/*` lifecycle for PicoKeys flashed with
  `polhenarejos/pico-openpgp` (OpenPGP 3.4.1 over USB/CCID) and
  `polhenarejos/pico-fido` (CTAP 2.3 / U2F over HID).
- Each task asks `gum choose openpgp fido` first, then branches.
- Replaces `files/base/system/usr/lib/kierownik/tasks/key/register`
  (single `pamu2fcfg --pin-verification | tee` call, overwrites mapping).
- Enrollment here owns device setup; login wiring stays in
  `next/1.0-autologin-fido.md` (FIDO greeter) and
  `next/1.1-autologin-gpg.md` (OpenPGP greeter).

## Current state (repo)

- `files/base/system/usr/lib/kierownik/tasks/key/register:1-6` enrolls
  touchless u2f and overwrites `/etc/u2f_mappings` via `tee`.
- `files/base/system/usr/bin/firstboot:215-218` repeats the touchless
  `pamu2fcfg --no-user-presence >> /etc/u2f_mappings` call.
- `recipes/base/systemd-homed.yml:1-19` ships `fido2-tools`,
  `gnupg2-scdaemon`, `pcsc-lite`, `pamu2fcfg`, `sssd`; enables
  `pcscd.service` + `pcscd.socket`.
- `opensc` (`openpgp-tool`, `pkcs15-tool`, `pkcs11-tool`,
  `opensc-pkcs11.so`) and `yubikey-manager` (`ykman`, pico-fido
  compatible) are NOT installed.
- No recipe installs the ccid driver (`pcsc-lite-ccid`); the old
  full-file `Info.plist` overlay under `files/wm/common/greetd/` is
  deleted. Stock plist from the driver package is patched at build
  time by `files/scripts/base/pico-key-ccid.sh` (stdlib plistlib,
  idempotent, asserts array alignment). Missing pairs: `0x2E8A:0x10FF`
  (Pico OpenPGP), `0x2E8A:0x10FE` (pico-fido), `0xFEFF:0xFCFD`
  (SDK fallback).
- `recipes/base/usbguard.yml` ships `usbguard` but service is disabled
  by default; `tasks/usbguard/setup` toggles via `generate-policy` +
  `enable --now`. No per-device allow flow exists. With usbguard
  active and no rule, the Pico is blocked → device checks fail with
  misleading "no device" errors.
- `files/scripts/common/fetch_gh_latest_tag` is build-time only
  (`/tmp/files/scripts/`, used by `non-packaged-tools.sh`,
  `zed/install.sh`, `voxtype/install.sh`); never shipped to target.
  Runtime download must inline `curl|jq` instead. `jq` is on-image
  (`tools.yml`); `curl` is not proven on target (only build env + llm
  images), so the new recipe module adds it.
- Upstream facts: default UF2 VID/PID `2E8A:10FF` (openpgp) /
  `2E8A:10FE` (fido), fallback `FEFF:FCFD`; RSA4096 on-card gen
  ~1000s; FIDO privates non-exportable except Pico Vault
  authenticated export (`docs/vault` upstream); 24-word backup via
  PicoKey App.

## Design

- New recipe module `recipes/base/pico-key.yml`, added to
  `recipes/base/all.yml` via `from-file: base/pico-key.yml`:
  - `dnf`: `opensc`, `yubikey-manager` (verified on Fedora:
    0.27.1 / 5.9.2), `pcsc-lite-ccid` (the actual driver; previously
    no recipe installed it), `curl` (runtime UF2 download;
    `jq` already in `tools.yml`).
  - `files`: `source: base/pico-key` ships
    `usr/lib/kierownik/tasks/key/{init,create,copy,update,_usbguard}`.
  - `script`: `base/pico-key-ccid.sh` appends the 3 Pico VID:PID
    pairs to the driver plist (runs after dnf, all images incl. N100).
- Tasks live in the new overlay (shipped by `pico-key.yml`
  `source: base/pico-key`): `files/base/pico-key/usr/lib/kierownik/tasks/key/{init,create,copy,update}`,
  `#!/usr/bin/env bash`, `set -oue pipefail`, `gum` only, `#MISE description`
  set so `krw` picker lists them, no positional args.
- Shared preamble: mode choose, then source
  `files/base/pico-key/usr/lib/kierownik/tasks/key/_usbguard` (leading
  `_` = `krw` picker skips it). Helper is a no-op when
  `usbguard.service` is inactive (default). When active, it matches
  the Pico in `usbguard list-devices` by VID:PID
  (`2e8a:10ff`/`2e8a:10fe`/`feff:fcfd`) and persists
  `run0 usbguard allow-device -p <id>` before the device checks run.
  Allow by VID:PID, not serial (survives `key/update` reflash churn;
  clone caveat same as `1.0` allowlist: rule = availability, auth stays
  U2F challenge / OpenPGP signature). Then fail fast with
  `gum log -sl error` when `gpg --card-status` (openpgp) or
  `fido2-token -L` (fido) is empty.
- `key/init` (first-time device setup):
  - openpgp: `gum input --password` for PW1/PW3/reset code + holder
    name; scripted `gpg --card-edit` admin (set PINs, name, lang,
    KDF-on, UIF press-confirm on); factory-reset behind second
    `gum confirm`.
  - fido: `fido2-token -L` pick, set/change PIN (`fido2-token -C`,
    verified on libfido2 1.16.0; `-S` is authenticator-config, not PIN),
    require touch/UV; point to PicoKey App for 24-word backup.
- `key/create` (credentials stay on device):
  - openpgp: `gum choose generate move`; generate ed25519 is fully
    non-interactive (positional `--command-fd` answers for GnuPG 2.4
    prompts, PIN via loopback, identity defaults from `~/.identity`);
    generate rsa4096 stays guided-interactive; move via `keytocard`
    from `gpg/init` host key picked with `gum choose`; write
    `pcsc-shared` into `~/.gnupg/scdaemon.conf`.
  - fido: login enroll `pamu2fcfg --pin-verification | run0 ... append`
    to `/etc/u2f_mappings` (append, never `tee` overwrite); hint
    `systemd-cryptenroll --fido2-device`, no auto-enroll.
  - usbguard (active only): Pico must already be authorized by the
    preamble helper or enroll reads fail; no extra step here.
- `key/copy` (pubs out, secrets never leave):
  - openpgp: same pattern as `gpg/copy-sign-pub` + `copy-ssh-pub`:
    `gpg --armor --export`, `gpg --export-ssh-key`,
    `ssh-keygen -D /usr/lib64/opensc-pkcs11.so -e`; `gum style` show +
    `gum confirm` → `wl-copy`.
  - fido: `fido2-token -L -I` info only; document Vault export +
    PicoKey App instead of raw export.
- `key/update` (UF2 reflash):
  - latest tag inline (no `fetch_gh_latest_tag` on target):
    `TAG=$(curl --silent --retry 3 "https://api.github.com/repos/<repo>/releases/latest" | jq -r '.tag_name // empty' 2>/dev/null || true)`.
    Empty `TAG` (offline / API rate limit) → `gum input` for manual
    tag; download fail → `gum input` for local UF2 path, same BOOTSEL
    flow after.
  - `gum choose` pico (RP2040) / pico2 (RP2350) asset;
    `https://github.com/<repo>/releases/download/<TAG>/<asset>`;
    `gum confirm` destructive warning (wipes keys → run `key/copy`
    first); `gum spin` poll for BOOTSEL mass storage, `cp *.uf2`,
    verify re-enumeration.
  - usbguard (active only): BOOTSEL bootloader exposes a different
    VID:PID than runtime — call the helper again inside the BOOTSEL
    poll loop so the mass-storage device gets authorized too.
- `firstboot:215-218`: delegate to `key/create` fido path or minimum
  drop `--no-user-presence` + keep append.

## Validation

- `mise run check:lint` (note: lint `shellcheck`/`shfmt` only cover
  `*.sh` + `.mise/tasks/*` — extensionless `tasks/key/*` need manual
  `shellcheck -S warning` + `shfmt -d -i 2 -ci`).
- Plist script tested locally: strip 3 pairs → run → all back,
  arrays aligned, valid XML; second run no-op (idempotent).
- `bluebuild build recipes/krw-5290.yml`
- VM + USB passthrough: `gpg --card-status`, `pkcs15-tool -D`,
  `fido2-token -L`, `pamtester` round-trip; each task with device
  absent / present / wrong PIN.
- Offline: empty `TAG` → manual tag input → local UF2 path; no
  hard network requirement.
- usbguard off: all `key/*` unchanged (helper no-op). usbguard on:
  `key/create` errors clearly without rule, authorizes, retry
  succeeds; `key/update` survives runtime→BOOTSEL→runtime without
  manual `usbguard` steps; `rules.conf` diff shows only intended
  `allow vid … pid …` lines.
- Open on hardware: UF2 asset names per board (pattern
  `pico_<fw>_<board>-<tag>.uf2` seen at v5.0/v8.0, re-verify),
  BOOTSEL VID:PID (pico vs pico2), `usbguard allow-device -p` flag
  name on Fedora 44.

# Homed LUKS homes bound to FIDO2 / Pico OpenPGP

## Goal

- Encrypt user homes (`--storage=luks`) and unlock them with the
  Pico: FIDO2 (`--fido2-device`) and/or OpenPGP PKCS#11 token
  (`--pkcs11-token-device`), password as fallback, recovery key held
  offline.
- Today homes are plaintext `--storage=directory`
  (`files/base/system/usr/bin/firstboot:196-206`), so homed's token
  bindings have nothing to bind to and FIDO/GPG live purely in PAM.

## Current state (repo)

- `firstboot:196-206`: `homectl create $USERNAME
  --password-change-now=false --storage=directory --fs-type=btrfs`,
  then copies `/tmp/skel` into `/var/home/$USERNAME.homedir/`.
- `recipes/base/systemd-homed.yml`: enables `systemd-homed`, selects
  `authselect ... with-systemd-homed ... with-pam-u2f`.
- FIDO login = `pam-u2f` + `/etc/u2f_mappings` (see
  `next/1.0-autologin-fido.md`); Pico lifecycle = `krw key/*` (see
  `next/3.2-pico-key-tasks.md`). Neither touches homed records.
- `next/1.0` notes home is unencrypted, so autologin adds no
  disk-encryption bypass — LUKS homes change that calculus
  (stolen laptop + autologin key = decrypted home).

## Design

- `firstboot`: `homectl create` with `--storage=luks`
  (`--fs-type=btrfs` stays); after create, enroll tokens:
  `homectl update $USERNAME --fido2-device=yes` (touch/PIN at enroll)
  and/or `--pkcs11-token-device=yes` for the Pico OpenPGP auth key;
  generate recovery key (`homectl --recovery-key`) and force the user
  to store it offline before finishing (abort = remove home).
- Existing installs: migrate by `homectl ... update --storage=luks`
  only works on re-create; real path is backup (`key/copy` pubs +
  data copy out), `homectl remove`, `homectl create --storage=luks`,
  restore. Provide a `homectl-migrate` task, never auto-run.
- Auth flow: greeter PAM collects password OR token; homed unlocks
  LUKS on success. Keep password enrollment mandatory
  (`--password-hint` set) so a lost Pico never bricks the account.
- `1.0` autologin shortcut must be re-evaluated under LUKS: with an
  encrypted home, presence-only autologin needs homed unlock without
  auth — either drop autologin for LUKS users or accept it only with
  an already-unlocked home. Default: LUKS homes skip autologin.

## Risks

- Lockout: lost Pico + lost recovery key + forgotten password = dead
  home. Mitigate with mandatory password + printed recovery key.
- `pcscd`/scdaemon exclusivity at greeter time for PKCS#11 unlock
  (same contention as `1.1` §4, now on the unlock path, not just login).
- FIDO2 UV/PIN policy on the Pico must match homed expectations;
  verify `homectl inspect` shows `fido2Device: yes` after enroll.

   from `pico-key.yml`).
3. Revisit: `next/1.0-autologin-fido.md` allowlist vs LUKS (default off

## Validation

- `mise run check:lint`
- VM: fresh `firstboot` → LUKS home → login via password, via Pico
  FIDO2, via Pico PKCS#11; wrong PIN fails; recovery key unlocks;
  `homectl inspect` shows bindings.
- Migration dry-run on a scratch user (backup → remove → re-create
  luks → restore → diff).

## Out of scope

GPG-data-at-rest beyond home (that's disk-level cryptsetup),
multi-user shared homes, TPM2 binding (no TPM story in repo yet).

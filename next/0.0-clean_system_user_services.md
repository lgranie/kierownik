# Clean system user services (greetd UID 967)

## Goal

- Stop wasteful user units from running under the `greetd` system user (UID 967).
- Keep greeter functional: `greetd.service` + `noctalia-greeter-session -- --session hyprland-uwsm` + user D-Bus + logind seat.
- Extend the existing `ConditionUser=!@system` pattern so the greeter user manager starts the minimum set.

## Design

Gate greeter-irrelevant user units with user conditions so only real users (`lgranie`, homed users) get them. Options, in order of preference:

1. `ConditionUser=!greetd` drop-ins under `files/wm/common/greetd/` (most targeted, survives package updates):
   - `usr/lib/systemd/user/gnome-keyring-daemon.service.d/10-greeter.conf`
   - `usr/lib/systemd/user/gnome-keyring-daemon.socket.d/10-greeter.conf`
   - `usr/lib/systemd/user/pipewire.socket.d/10-greeter.conf`
   - `usr/lib/systemd/user/pipewire-pulse.socket.d/10-greeter.conf`
   - `usr/lib/systemd/user/podman.socket.d/10-greeter.conf`
   - `usr/lib/systemd/user/systemd-tmpfiles-clean.timer.d/10-greeter.conf`
   - `usr/lib/systemd/user/user-flatpak-setup.timer.d/10-greeter.conf`
   - `usr/lib/systemd/user/systemd-ask-password.socket.d/10-greeter.conf` (if verified unused)
   - Each file: `[Unit]\nConditionUser=!greetd`.
2. Alternative if `!greetd` matching proves brittle: `ConditionUser=!@system` (already used repo-wide for `@system` users; `greetd` UID 967 is a system user, real users are not). This matches the existing convention but is broader — it would also gate any future system user, which is likely desired anyway.
3. Do NOT gate: `dbus.socket` / `dbus-broker.service`, `basic.target`, `sockets.target`, `session.slice`, `app.slice`, `systemd-tmpfiles-setup.service` (unless follow-up measurement shows safe).
4. Do NOT touch system scope: `greetd.service`, `user@967.service`, `session-c1.scope` are required PAM/logind plumbing.

Note: `podman.socket` is enabled in `recipes/base/systemd-services.yml` under `user.enabled`. A drop-in condition is preferable to removing the enable, so real users keep on-demand Podman.

### Why greetd pulls so much and others do not

Greetd uses the login path; the others use the service path:

- Greetd PAM stack (`/etc/pam.d/greetd-greeter`: `pam_permit` auth/account + `pam_unix`/`pam_systemd` session) opens a PAM session, `pam_systemd` triggers logind session `c1` (class `greeter`) + `manager-early` session `1`, which starts `user-runtime-dir@967.service` + `user@967.service`. Manager PID 1165 boots `systemd --user`, reaches `default.target`, and pulls every enabled user socket/timer/service.
- `User=` daemons never get a PAM session, never get a logind session, never start `user@UID.service`, never reach `default.target`. PID 1 just forks, sets UID, execs one daemon.

### Why the login path is mandatory for greetd

Greetd is the display manager on `tty1` (replaces getty/GDM/SDDM). It must authenticate lgranie, enforce PAM policy, allocate seat/devices/runtime dir, hand off to the Hyprland session, and return to the greeter on logout:

- PAM: `pam_unix(greetd-greeter:session)` for greetd, `pam_systemd_home` + `pam_unix(greetd:session)` for lgranie.
- logind: session `c1` grants DRM master, input via libseat logind backend (`Seat opened with backend 'logind'` after `Could not connect to socket /run/seatd.sock: No such file or directory`), VT switching, idle tracking, `PrepareForSleep` handling watched by `noctalia-greeter`.
- Config: `/etc/greetd/config.toml` (`vt = 1`, `default_session` command `noctalia-greeter-session -- --session hyprland-uwsm`, `user = "greetd"`). Daemon stays root (PID 1145) to verify credentials; only the session child runs as UID 967 in `session-c1.scope` with `WAYLAND_DISPLAY`, `XDG_RUNTIME_DIR=/tmp/noctalia-runtime-967`, `XDG_SESSION_TYPE`, `XDG_VTNR`.
- A plain `User=` system service cannot prompt for password, verify U2F/PIN, own the VT seat, create `/run/user/*`, or start a scoped user session.

### New-path evaluation (from discussion)

- Variant 1 (new activation path, experimental): strip `session optional pam_systemd.so` from `/etc/pam.d/greetd-greeter`, enable `seatd.service`, put greetd in `seat` group. Result would be zero logind session, zero `user@967.service`, zero `default.target` bloat. Cost: breaks logind VT/ACL/session tracking, SELinux `xdm_t` expectations, `PrepareForSleep` watcher must move to system bus; needs full DRM/input/VT/suspend retest in VM.
- Variant 2 (slim login path, recommended): keep PAM + logind + `user@967.service`, gate bloat with `ConditionUser=!greetd` drop-ins. Keeps auth handoff intact.
- Variant 3 (system-service greeter) is impossible for the auth part: the daemon must stay root; only the session child path can change.

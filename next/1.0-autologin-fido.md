# Greetd FIDO2 conditional autologin (V2, shared allowlist)

## Goal

- Boot with registered FIDO2 key plugged → autologin straight to
  `hyprland-uwsm` as the mapped user, no touch/PIN (presence-only).
- Otherwise (no key / unknown key / serial-less key / no enrolled user)
  → normal `noctalia-greeter` login. Existing `pam-u2f` login stays
  unchanged.

## Current state (repo)

- Login: `greetd` + `noctalia-greeter-session -- --session hyprland-uwsm`
  (`files/wm/common/greetd/etc/greetd/config.toml`, user `greetd`).
- HW auth already wired: `recipes/base/systemd-homed.yml` installs
  `fido2-tools` / `pam-u2f` / `pamu2fcfg` / `pcscd` / `sssd` and runs
  `authselect select sssd ... with-pam-u2f`.
- `files/base/system/usr/bin/firstboot:215-218` enrolls
  `pamu2fcfg --no-user-presence >> /etc/u2f_mappings`; `pam_u2f.conf`
  already sets `pinverification=0 userpresence=0 userverification=0`.
- Session binary: `hyprland-uwsm.desktop` runs
  `uwsm start -e -D Hyprland hyprland.desktop`.
- `usbguard` is installed but disabled by default
  (`recipes/base/usbguard.yml`).

## Design

### 1. Shared allowlist (the binding)

One shared file, as agreed:

- Path: `/etc/kierownik/autologin-keys`, format `user serial` per line,
  `root:root 0600`, created via `tmpfiles.d`
  (`f /etc/kierownik/autologin-keys 0600 root root -`).
- Serial source: sysfs (`/sys/bus/usb/devices/*/idVendor`,
  `idProduct`, `serial`, `product`) — no new package dependency
  (`usbutils`/`ykman` are not in the target image; `fido2-tools` is,
  but `fido2-token -L` does not report serials).
- Keys without serial (e.g. Yubico Security Key): installer warns and
  skips the allowlist entry → greeter-only via `pam-u2f`, never
  autologin.
- Multi-key supported (append one line per key); unregister task
  removes the line.

### 2. Boot-time gate via greetd `initial_session`

`initial_session` runs exactly once per boot (greetd runfile
semantics), so logout still lands on the greeter — the desired
behaviour. No hotplug daemon in v1; key inserted after boot means
normal greeter login.

```toml
# files/wm/common/greetd/etc/greetd/config.toml
[terminal]
vt = 1

[initial_session]
command = "/usr/libexec/kierownik/greetd-autologin"
user = "root"

[default_session]
command = "noctalia-greeter-session -- --session hyprland-uwsm"
user = "greetd"
```

Wrapper `/usr/libexec/kierownik/greetd-autologin`
(`#!/usr/bin/env bash`, `set -oue pipefail`, no `gum` — no TTY at
greetd time):

1. Resolve user: first field of `/etc/kierownik/autologin-keys`,
   fallback to first field of `/etc/u2f_mappings`. None (e.g. fresh
   `firstboot` not done) → exit `0` → greeter.
2. Presence gate: `fido2-token -L` output non-empty.
3. Binding gate: at least one sysfs USB device serial matches an
   allowlist serial for that user. No match → exit `0` → greeter
   (blocks attacker-with-random-key).
4. Match → `exec runuser -u "$USER" -- uwsm start -e -D Hyprland
   hyprland.desktop`.
5. Log allow/deny reason to the journal (`logger -t greetd-autologin`)
   for `journalctl -u greetd` debugging.

`initial_session.user = "root"` keeps the username dynamic for the
single-user `homectl` box; the PAM session is established by greetd
and the target session runs via `runuser`.

### 3. Enrollment UX

- Helper `krw-usb-serials`: enumerates sysfs candidates as
  `VID:PID serial product` lines for `gum choose`.
- `firstboot` (after the existing `pamu2fcfg` block): prompt to pick
  the just-inserted key, append `"$USERNAME $SERIAL"` to the shared
  file.
- `register-u2f-key.fish`: same picker/append flow; also fix the
  current `tee`-overwrite of `/etc/u2f_mappings` → append.
- Add `unregister-u2f-key` task removing the serial line (and
  optionally the `u2f_mappings` line).

### 4. Hardening (agreed): presence-required `pam-u2f` fallback

The autologin shortcut above stays forgeable by design (USB serials
are clonable firmware strings). The greeter fallback, however, is a
real U2F challenge (the key signs a nonce with a non-exportable
credential) — today weakened to touchless by `--no-user-presence` at
enroll plus `userpresence=0` in `pam_u2f.conf`. Harden it so greeter
login demands a touch while staying passwordless:

- `files/wm/common/greetd/etc/security/pam_u2f.conf`:
  `userpresence=0` → `userpresence=1` (keep `pinverification=0
  userverification=0` and the `cue` prompt; no PIN, just touch).
- `files/base/system/usr/bin/firstboot:215-218`: drop
  `--no-user-presence` from the `pamu2fcfg` call so the enrolled
  credential requires presence.
- `files/base/tools/etc/fish/functions/register-u2f-key.fish`: drop
  `--pin-verification` (plain `pamu2fcfg` touch enroll) and fix the
  `tee`-overwrite of `/etc/u2f_mappings` → append.
- Existing `u2f_mappings` entries enrolled touchless must be
  re-enrolled (one `register-u2f-key` run per key); document this as a
  migration note.

     (+ fix overwrite bug, + unregister task)
3. Caveats to document in README/section:
   - Presence ≠ authentication for the autologin shortcut: stolen
     laptop + cloned-serial key = desktop. Home uses
     `--storage=directory` (unencrypted), so autologin adds
     no disk-encryption bypass, but physical theft resistance is nil.
     The greeter fallback (§4) remains a real unforgeable challenge
     (U2F signature) + touch.
   - If `usbguard` is ever enabled, add a HID allow-rule for the key
     or autologin breaks closed.
